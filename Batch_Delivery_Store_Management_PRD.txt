**Product Requirements Document (PRD): Batch Delivery & Store Management System**

1. ข้อมูลภาพรวม (Project Overview) สร้างระบบบริหารจัดการที่ครอบคลุมตั้งแต่หน้าเว็บขายสินค้าไปจนถึงการจัดส่งในรูปแบบ "การส่งเป็นรอบ" (Batch Delivery) เพื่อรองรับการส่งสินค้าหลายจุดหมายในเส้นทางเดียว โดยเน้นการเพิ่มประสิทธิภาพการจัดเส้นทาง (Route Optimization) เพื่อประหยัดเวลาและลดต้นทุนค่าน้ำมันสำหรับการวิ่งส่งในพื้นที่ต่างจังหวัด 

2. กลุ่มผู้ใช้งาน (Target Users) 

* Admin (เจ้าของร้าน): จัดการรายการสินค้า ตรวจสอบออเดอร์ วางแผนรอบส่ง และจัดการเส้นทาง 


* Driver/Rider (ผู้ส่งสินค้า): ดูรายการออเดอร์ที่ต้องส่งตามลำดับและใช้ระบบนำทางไปยังบ้านลูกค้า 


* Customer (ลูกค้า): เลือกซื้อสินค้า ปักหมุดที่ตั้งที่แม่นยำ และติดตามสถานะการส่ง 



3. ขั้นตอนการทำงานของระบบ (Conceptual Workflow) 

1. Product Management: Admin เพิ่มและจัดการรายการสินค้าผ่านระบบหลังบ้าน 


2. Product Selection: ลูกค้าเลือกสินค้าที่ต้องการลงรถเข็นผ่านหน้าเว็บ 


3. Order Collection: ระบบรวบรวมรายการสั่งซื้อที่ชำระเงินแล้วพร้อมพิกัด (Lat, Lng) ที่ลูกค้าปักหมุดไว้ 


4. Batch Creation: Admin เลือกกลุ่มออเดอร์ที่อยู่ใกล้กันจากแผนที่เพื่อสร้างเป็น 1 รอบการส่ง (Batch) 


5. Route Optimization: ระบบคำนวณลำดับการส่งที่สั้นที่สุดด้วยหลักการ TSP (Traveling Salesman Problem) 


6. Driver Dispatch & Tracking: ส่งข้อมูลให้ผู้ส่ง และอัปเดตสถานะการจัดส่งรายจุดจนจบ Batch 



4. คุณสมบัติหลักที่ต้องมี (Core Features) 

**4.1 สำหรับลูกค้า (Storefront & Checkout)** 

* Product Catalog: แสดงรายการสินค้าพร้อมรูปภาพ รายละเอียด และราคา 


* Shopping Cart: ระบบเลือกสินค้าลงรถเข็นและคำนวณราคาก่อนชำระเงิน 


* Address Pinning: ระบบให้ลูกค้าปักหมุดตำแหน่งบนแผนที่เองในขั้นตอนเช็คเอาต์เพื่อความแม่นยำ 


* Distance Restriction: ตรวจสอบระยะทางจากร้าน หากเกิน 15-20 กม. ระบบจะแนะนำให้ใช้ขนส่งเอกชน 


* Order Tracking: หน้าสำหรับดูสถานะว่าสินค้าอยู่ในรอบการส่งใด และเป็นลำดับที่เท่าไหร่ 



**4.2 สำหรับ Admin (Management Dashboard)** 

* Product Management: ระบบเพิ่ม, แก้ไข, ลบรายการสินค้า และจัดการสต็อก 


* Interactive Map & Batching: แสดงหมุดออเดอร์ค้างส่งและเครื่องมือเลือกกลุ่มออเดอร์ (Lasso/Multi-select) 


* Route Optimizer: ปุ่มสั่งจัดเรียงลำดับการส่งอัตโนมัติเพื่อให้ได้เส้นทางที่สั้นที่สุด 



**4.3 สำหรับคนขับ (Rider Interface)** 

* Delivery Sequence List: รายการที่อยู่ลูกค้าเรียงตามลำดับที่เหมาะสม 1, 2, 3... 


* One-Click Navigation: ปุ่ม "Navigate" เพื่อเปิด Google Maps นำทางไปยังบ้านลูกค้าทันที 


* Status Update: ปุ่มกดยืนยันการเริ่มส่ง และยืนยันการส่งสำเร็จในแต่ละจุด 



5. ข้อกำหนดทางด้านข้อมูล (Data Requirements) 

* Products: ข้อมูลรายละเอียดสินค้าและสต็อก (id, name, description, price, stock, image_url) 


* Orders: ข้อมูลลูกค้า รายการที่สั่ง และพิกัด (id, customer_info, product_list, total_price, lat, lng, status) 


* DeliveryBatch: ข้อมูลหัวข้อรอบการส่ง (id, driver_id, batch_status, created_at) 


* BatchItems: ลำดับการส่งในแต่ละรอบ (id, batch_id, order_id, sequence_no) 



6. เครื่องมือทางเทคนิค (Technical Stack) 

* Platform: พัฒนาเป็น Web App (PWA) เพื่อความลื่นไหลบนมือถือโดยไม่ต้องโหลดแอป 


* Map Library: Leaflet.js สำหรับ Admin Dashboard (เบาและปรับแต่งง่าย) 


* Routing API: Google Maps Directions API พร้อมพารามิเตอร์ optimizeWaypoints: true 


* Pricing Engine: ระบบคำนวณค่าส่งอัตโนมัติตามระยะทางจริง (Distance-Based Fee) 



7. แผนการขยายผลใน 1 ปี (Future Roadmap) 

* Driver Management: ระบบจัดการข้อมูลและคัดกรองคนขับตามประเภทรถ 


* Proof of Delivery (POD): ฟีเจอร์ถ่ายรูปสินค้าเมื่อส่งสำเร็จเพื่อยืนยันในระบบ 


* Performance Tracking: เก็บข้อมูลเวลาที่ใช้ส่งแต่ละจุดเพื่อประเมินประสิทธิภาพ 



8. ข้อควรระวัง (Constraints) 

* Capacity Limit: ระบบต้องเช็คปริมาณหรือน้ำหนักสินค้ารวมใน 1 รอบ ไม่ให้เกินขีดความสามารถของรถ 


* Batch Window: จำกัดจำนวนจุดส่งในรอบที่ระยะทางไกล เพื่อไม่ให้ลูกค้าลำดับท้ายรอนานเกินไป
