สวัสดีครับ ในฐานะ Project Manager และ Lead Developer ผมได้ตรวจสอบ Source Code, PRD v2, โครงสร้างฐานข้อมูล (SQL) และการตั้งค่าล่าสุดของโปรเจกต์คุณอย่างละเอียดแล้วครับ

ถือว่าโปรเจกต์มีการวางรากฐานทางเทคนิค (Foundation) ได้แข็งแกร่งและสอดคล้องกับ Requirement มาก โดยเฉพาะการเปลี่ยนผ่านมาใช้ @supabase/ssr สำหรับระบบ Middleware ครับ

นี่คือรายงานสรุปสถานะของโปรเจกต์และแผนงานถัดไปครับ:

1. Current Progress (สรุปสิ่งที่ทำเสร็จแล้ว)
Infrastructure & Tech Stack:

Framework: Next.js (App Router), Tailwind CSS, TypeScript ทำงานร่วมกันได้สมบูรณ์
Routing & Auth: สร้างระบบ Role-based Access Control (RBAC) ได้ยอดเยี่ยมผ่าน proxy.ts (Middleware) ที่ดักจับและแยก Role (Super Admin, Branch Admin, Rider) ได้อย่างฉลาด พร้อมมีระบบ Fallback Redirect (เตะกลับหน้าแรกของตัวเองถ้าเข้าผิดสิทธิ์)
State Management: วางระบบ Zustand (branchStore.ts) ไว้รองรับ Multi-branch ได้แล้ว
Database (Supabase):

โครงสร้างตารางหลัก (Schema) ถูกออกแบบไว้ครอบคลุมตาม PRD v2 (sql.txt)
มีไฟล์ Migration 01_add_branch_id.sql เพื่อเพิ่ม branch_id เชื่อมความสัมพันธ์ให้กับ orders และ delivery_batches รองรับการแยกข้อมูลของสาขาแล้ว
Core Logic & Features:

Customer Location: หน้าแรกลูกค้า (app/(customer)/page.tsx) มีแผนที่ Leaflet ที่รองรับ Geolocation คำนวณหาสาขาที่ใกล้ที่สุดได้ (ผ่าน BranchLocatorMap.tsx) และโหลดแบบ Dynamic SSR เรียบร้อย
Route Optimization: มี API Backend (route.ts) สำหรับรับพิกัดไปยิง Google Maps API เพื่อทำ TSP (Traveling Salesman Problem) คืนค่าเส้นทางที่สั้นที่สุดได้
User Management: มี API สำหรับ Super Admin (/api/admin/users/route.ts) ที่ใช้ SUPABASE_SERVICE_ROLE_KEY มอบสิทธิ์ในการสร้างบัญชีข้าม RLS ได้
Login Flow: หน้า Login นำ Supabase Auth UI มาใช้ และตรวจสอบ Session เพื่อ Redirect ได้ครบถ้วน

3. Prioritized Roadmap (แผนงานถัดไป Step-by-Step)
เพื่อให้โปรเจกต์นี้ทำงานได้จริงตั้งแต่ต้นน้ำยันปลายน้ำ (MVP - Minimum Viable Product) ขอแนะนำให้ทีมพัฒนาเดินตามลำดับความสำคัญนี้ครับ:

Step 1: Dashboard Routing & User Setup (High Priority)

อัปเดตหน้า /dashboard ให้เช็ค Role ผู้ใช้งานแล้ว Redirect ไปยังหน้าแรกของแต่ละ Role อัตโนมัติ (รับไม้ต่อจากหน้า Login)
สร้าง UI พื้นฐานให้ Super Admin สามารถเรียกใช้ API สร้าง User เพื่อจำลองบัญชีให้ Branch Admin และ Rider ทดสอบระบบได้
Step 2: Customer Ordering Flow (High Priority)

สร้างหน้า Storefront ดึงข้อมูลจากตาราง branch_inventory (JOIN กับ products) โดยกรองตาม branchId
สร้างหน้า Checkout ให้ลูกค้าปักหมุดแผนที่ (Leaflet) -> คำนวณระยะทางว่าอยู่ในรัศมีสาขาหรือไม่ -> บันทึกลงตาราง orders เพื่อให้เรามี Data จริงไปใช้ทำ Route Optimization
Step 3: Branch Admin Batching Map (Medium-High Priority)

อัปเดตหน้า BatchMap.tsx ให้ Fetch ข้อมูลจากตาราง orders (ที่ status='pending' และ branch_id ตรงกับแอดมิน)
นำหมุดออเดอร์มารวมกัน (Lasso/Select) กดส่ง API ไปหา route.ts และรับ sequence_no (ลำดับที่จัดเรียงแล้ว) มาบันทึกลงตาราง delivery_batches พร้อม Assign ให้ Driver
Step 4: Rider Mobile View (Medium Priority)

พัฒนาหน้า Rider ดึง batch_items ของตัวเองมาแสดง
เพิ่มปุ่มเปิดแอป Google Maps นำทาง (Deep-link URI) และปุ่ม "จัดส่งสำเร็จ"
4. Technical Requirements & Warnings (คำแนะนำด้านเทคนิคและความปลอดภัย)
ก่อนเขียนโค้ดเพิ่ม ขอให้ Lead Developer / ทีมงาน ระวัง 4 เรื่องนี้ครับ:

Row Level Security (RLS) is Crucial:
ตอนนี้โครงสร้าง Database เพิ่งมีแค่ Schema แต่ ยังไม่ได้เปิด RLS หรือเขียน Policy
คุณต้องสร้าง RLS บนตาราง orders และ branch_inventory ทันที โดยมีเงื่อนไข (Policy) ว่า: auth.jwt() -> 'user_metadata' ->> 'role' = 'branch_admin' AND branch_id = (select branch_id from users where id = auth.uid()) เพื่อป้องกันไม่ให้สาขา A เห็นข้อมูลของสาขา B
ลบไฟล์ middleware.ts ตัวเก่าทิ้ง:
คุณมีการสร้างไฟล์ proxy.ts ที่ใช้ @supabase/ssr ซึ่งถูกต้องและทันสมัยกว่ามากแล้ว แต่ในระบบยังมีไฟล์ middleware.ts ที่ใช้ @supabase/auth-helpers-nextjs ค้างอยู่ (ซึ่ง Library นี้ Supabase ประกาศ Deprecated แล้ว)
Action: แนะนำให้ลบ middleware.ts ทิ้งไป แล้วเปลี่ยนชื่อ proxy.ts มาเป็น middleware.ts แทนครับ เพื่อให้ Next.js ทำงานได้ถูกต้องโดยไม่มี Middleware ทับซ้อนกัน
Google Maps API Key:
เนื่องจาก API route.ts ถูกออกแบบมาให้เป็น Server-side API อยู่แล้ว (มีการเรียกใช้ process.env.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY)
แนะนำให้เอาคำว่า NEXT_PUBLIC_ ออกจากชื่อตัวแปร (เช่นเปลี่ยนเป็น GOOGLE_MAPS_SERVER_KEY ใน .env.local) เพื่อไม่ให้ Next.js เผลอเอา Key ของคุณไปฝังในฝั่ง Client ซึ่งอาจถูกแกะไปใช้จนเสียเงินฟรีได้
Supabase TypeScript Types:
เพื่อป้องกันการเขียนชื่อคอลัมน์ผิด แนะนำให้รันคำสั่ง npx supabase gen types typescript --project-id "YOUR_PROJECT_ID" > src/lib/database.types.ts แล้วนำมาครอบ Supabase Client โค้ดจะมี Autocomplete ใช้งานง่ายขึ้นเยอะครับ
ถ้าพร้อมลุยเฟสต่อไปแล้ว บอกผมได้เลยครับว่าจะให้เริ่มเขียน หน้า Checkout และแผนที่ปักหมุดของลูกค้า หรือ การเขียน RLS Policies ก่อนดีครับ!
